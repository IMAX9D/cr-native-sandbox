# 最多两个有序操作：训练端探针

入口：仓库根目录运行 `python experiment_hokoff_ordered.py`（conda `r2dreamer`）。默认从固定 4 tick 正式模型读取状态编码器，编码器冻结；两个新解码器各短训 500 次更新。不改原训练、旧 checkpoint 或游戏推理。

## 表达方式

一次固定 4 tick 观察对应原始区间 `[t,t+4)`：

- 第一步：STOP / 下牌 / 技能。
- 下牌继续选择卡牌类型、位置和原始 tick 偏移；技能选择技能类型和偏移，没有位置。
- 第二步可读取第一步的操作类型、卡牌或技能类型、位置（仅下牌）、tick 偏移，再选择 STOP / 下牌 / 技能。
- 第一步 STOP 表示零操作；第二步 STOP 表示一个操作；第二次操作后达到上限，结束此次序列。
- 第二个操作的 tick 必须大于第一个。第一步在窗口最后一个 tick 时，第二步只能 STOP。

这里保留专家真正的时间间隔，没有把两个动作都提前到观察时刻。源编译器拒绝同侧同 tick 的操作冲突，因此该实验不声称覆盖同 tick 连续命令。

## 数据限制与范围

完整固定 4 tick 缓存中的双操作窗口：

| 来源 split | 双卡牌 | 卡牌→技能 | 技能→卡牌 | 合计 |
|---|---:|---:|---:|---:|
| validation（实际训练集） | 673 | 4 | 1 | 678 |
| train（实际验证集） | 7 | 0 | 0 | 7 |

训练时额外随机取 678 个单操作、678 个无操作窗口，与所有合格双操作窗口组成分层诊断样本。验证使用全部合格双操作窗口、各 256 个单操作/无操作窗口；另取 2048 个自然抽样的可监督窗口。三类训练样本的比例是本次探针设置，不是正式训练推荐，也不能据此直接部署其出牌阈值。

原始数据只有类型 token，没有精确费用、稳定英雄实例 ID，也没有任意候选卡牌的完整未来合法掩码。因此：

- 这是 **操作序列预测探针，不是可直接执行的宏动作策略**。
- 输出卡牌/技能类型，而非执行时手牌槽或英雄实例。未来执行端必须重新映射对象，校验费用、冷却、手牌与位置合法性，必要时重新观察。
- 标签只在专家真实执行 tick 校验合法性；不会把未来合法掩码输入模型或伪装成当前合法性证据。
- 同类型多个英雄导致目标不明确时，屏蔽整个窗口。未知标签、超过两个动作、跨角色/截断窗口同样屏蔽，不改成 STOP。
- 训练中的第一步专家动作只用于 teacher forcing 第二步；选中的专家卡牌也用于监督对应位置分布。这些是自回归条件，验证时全部使用模型自己的预测。
- 主干只读取当前及过去固定观察，不读取未来状态。动作窗口不因专家即将操作而改变观察时刻。

## 对照与复现

两组使用同一固定模型编码器、同一批窗口、同一初始化权重、同一更新顺序和步数：

- `unconditioned`：第二步只读取场景上下文及第二步标记，不读取第一步操作 embedding。
- `ordered`：第二步额外读取第一步操作 embedding。

两组均保留必须结束/时间严格递增的约束，因此 `unconditioned` 仍受第一步停止状态和 tick 上界约束。这不是与旧完整 BC 模型的直接性能对比，而是检验动作条件是否帮助新解码器的局部对照。卡牌/技能 token 分类头和解码 GRU 为新参数；复制旧模型的类型 embedding 和卡牌位置头。

```bash
cd /home/lenovo/gh/cr-native-sandbox
conda activate r2dreamer
python experiment_hokoff_ordered.py --steps 500
```

只用于短训诊断。脚本默认新建带时间戳的结果目录；指定 `--output` 时该目录必须尚不存在。没有自动续训，不会启动长训。`--source-checkpoint` 可指定原 fixed4 模型，架构和缓存校验必须一致。

结果包含：

- `data_audit.json`：所有双操作窗口的原始行号和顺序。
- `windows.json` / `sampling.json`：实际样本索引与剔除原因。
- `contract.json`：源模型/缓存摘要及实验设置。
- `features.pt`：冻结编码器输出和监督标签，用于本次探针复查。
- `unconditioned.pt` / `ordered.pt`：解码器参数及源编码器引用。**不是旧模型格式，不能传给原游戏推理或原评估脚本。**
- `results.json`：自由解码指标；`count_2_recall` 查看双操作能否被预测；`sequence_2_accuracy` 要求两次操作的类型、卡牌/技能类型和位置全部正确；`sequence_with_tick_accuracy` 还要求 tick 偏移正确。

只有 7 个验证双操作、没有技能混合验证例。即使短训指标提高，也不能据此证明组合策略改善战局。

## 已运行结果（2026-09-08）

结果目录：`/home/lenovo/cr-data/runs/hokoff-ordered-probe-20260908-v1`，详细解释见其中 `ANALYSIS.zh-CN.md`。

两组各 500 step，串行版最后批次 loss 更低，但自由解码倾向输出两次操作；诊断验证集的 7 条双操作都未完整预测正确。额外 `oracle_first_action_metrics` 给定正确首步、只评第二步：单次操作后正确 STOP 从对照 71.48% 到串行 81.64%，第二步内容完整正确两组均 1/7。没有充分的效果收益证据，不替换正式模型。
