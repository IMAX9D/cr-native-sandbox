# 第二轮性能优化结果：12×4 吞吐提升 21.1%

日期：2026-09-12。设备：F78，25 核 CPU 配额、92 GiB 内存、RTX 5090 D 32 GB。
模型：用户提供的 restart319051，4,804,205 个可训练参数，固定 4 tick 决策。

## 结论

**新旧路径的 12×4 对照共完成 384 场，聚合吞吐从 5,127.1 提升到 6,206.8 tick/s，提升 21.06%；每轮耗时降低 17.40%。** 所有对应种子的动作摘要、终局、出牌数量和总 tick 相同。

本轮减少 CPU 重复处理、宿主绑定开销及推理时的序列调度/CPU↔GPU 往返。没有修改权重、精度、物理时钟、出牌阈值、卡组或奖励，也没有通过跳过决策提速。

这是冻结策略的**对弈采集链路**优化，不含 PPO 反向训练；不能将 21.1% 直接当作完整训练系统或所有模型的收益。F78 保持开机，所有本轮测试进程已退出；本地人机盒子未动。

## 1. 高并发：最终采用的性能口径

12 个原生进程，每个驻留 4 局，12 个直接 GPU 策略实例。每次运行 2 波、共 96 场；使用同一组 96 个种子，顺序 A/B/B/A。

| 运行 | 版本 | 完成场数 | 总 tick | 出牌数 | 耗时 | 聚合 tick/s |
|---|---|---:|---:|---:|---:|---:|
| A1 | 原版 | 96 | 544,650 | 15,863 | 106.487 s | 5,114.7 |
| B1 | 优化版 | 96 | 544,650 | 15,863 | 87.642 s | 6,214.5 |
| B2 | 优化版 | 96 | 544,650 | 15,863 | 87.858 s | 6,199.2 |
| A2 | 原版 | 96 | 544,650 | 15,863 | 105.972 s | 5,139.5 |
| 平均 | 原版 | 96/次 | 544,650/次 | 15,863/次 | **106.230 s** | **5,127.1** |
| 平均 | 优化版 | 96/次 | 544,650/次 | 15,863/次 | **87.750 s** | **6,206.8** |

四次运行按种子逐局比较，动作摘要、最终 tick、胜负、皇冠数、出牌数全部相同。384 是重复执行的总场数，不是 384 个不同种子。

| 资源 | 原版两次 | 优化版两次 |
|---|---:|---:|
| 平均 CPU 核数 | 12.08 / 12.11 | 12.18 / 12.00 |
| 峰值显存 | 8,446 / 8,446 MiB | 8,446 / 8,446 MiB |

cgroup 内存含文件缓存等，不是模型独占内存；不据此声称优化版降低了总内存。GPU 利用率不是 FLOPS 或 SM 占用率。CPU 总占用相近但单位时间处理更多 tick，这是每份样本开销减少。

本轮未重新扫描 16/24 进程配置；12×4 是本次对照配置，不宣称已经找到新版本的全局最优并发数。

## 2. 实际修改

### CPU 历史窗口

旧路径对每个历史字段做逐元素 Torch 赋值。新 `FastHistory` 用 NumPy 一次构造数组，再零拷贝包装成 CPU Tensor。

严格过去事件、双方视角顺序、镜像格子、未知信息掩码、事件去重和重置规则保持不变。CPU 微测 3,000 次查询约 20.7 倍加速，但这只是小模块，不能宣称整条链路 20 倍。

### 观测状态复用

同一同步 prepare 组内，一局只规范化一次原始帧，双方使用各自的公开投影；finish 复用它所属的已准备帧，不再重复解析。

缓存持有原始帧身份，collate 后立即清空共享缓存，reset 清空待完成帧。只适用于本采集器不原地修改观测的同步生命周期；不是任意跨线程、跨 tick 的全局状态缓存。

### 原生宿主绑定

只有 create/step 真正需要内存读取器，bind/unbind 不再创建它。可选 `CR_NATIVE_RESIDENT_BIND_CACHE=1` 持有通过验证的 loader 引用，在同路径 bind/unbind 时复用；这个引用防止相关库被卸载/换址。

create/step 继续执行完整 RVA 校验；slot 存在性、参数范围、运行时路径检查保留。没有删除物理、攻击、寻路或结算逻辑。

### CUDA 在线推理调度

原模型的通用 recurrent 路径支持训练序列，需要 pack、排序、把长度送回 CPU、再 unpack。实际在线输入每次只有一个有效时间点。

新路径只允许 **eval + T=1 + 全部帧有效 + 无训练 loss mask**，直接调用同权重 LSTM；全有效的空间修正头也不再用布尔筛选/nonzero/index_add 选择同一批完整行。

历史维度、有限数和非负时间检查保留。训练模式、padding、非法历史、跨 reset 的旧帧明确拒绝。没有使用半精度、TF32、torch.compile 或 CUDA Graph。

## 3. CPU 分项变化

下表来自同一批 4 场、24,442 tick 的单进程无 CUDA trace 计时对照。它是 CPU 执行时间，不是 GPU 计算时间。

| CPU 阶段 | 原版 | 优化版 | 变化 |
|---|---:|---:|---:|
| 观测准备（含历史查询） | 9.162 s | 5.299 s | -42.2% |
| 动作解码 | 2.130 s | 0.735 s | -65.5% |
| 前向调用的 CPU 调度/运行时 | 6.452 s | 5.655 s | -12.4% |
| 全采集进程 CPU 时间 | 25.711 s | 20.677 s | -19.6% |

同组墙钟时间为 34.771→29.075 秒。计时程序与普通吞吐程序开销不同，不能混用分母。

原生绑定/解绑共 24,580 次：前轮同轨迹插桩约 3.041 CPU 秒，本轮约 0.041 CPU 秒。这个热点显著缩小，但这不是严格单因素的整机 ABBA 收益；不能据此给绑定缓存单独分配一个端到端提升百分比。

历史维护中的回执处理及 `_enrich_state` 深拷贝尚未优化；本轮也没有把 JSON 或游戏指针读取改写为 GPU 运算。

## 4. GPU 分项变化

同样三个窗口、合计 96 个在线循环的实际 CUDA 活动；原版数据来自前轮同轨迹 trace，新版来自本轮 trace。

| 活动 | 原版 | 优化版 |
|---|---:|---:|
| GPU 内核调用数 | 21,874 | 18,610 |
| 平均每循环内核调用数 | 227.9 | 193.9 |
| 累计内核活动时间 | 36.217 ms | 31.297 ms |
| 前向模型内核活动时间 | 30.655 ms | 25.737 ms |
| GPU→CPU 传输事件数 | 1,056 | 480 |

小内核调用减少约 **14.92%**；GPU→CPU 传输事件减少约 **54.55%**。并不表示传输字节同比下降，也不是显卡利用率或整机吞吐的提升百分比。

### CPU 工作能不能搬到 CUDA？

可以选择性搬：合批后的坐标运算、归一化、网格聚合适合进一步研究。但目前输入仍是 CPU 侧的原生对象/JSON，盲目搬小操作会增加复制、启动和同步开销。

本轮有效路线是：**让 CPU 少做重复工作，让 GPU 少接收细碎任务，让两者少往返**，而不是简单增加 CUDA 计算量。指针读取、动态对象解析和对局生命周期仍留在 CPU；本轮未实现 GPU 版观测编码器。

## 5. 单进程结果与正确性

普通吞吐驱动的正反对照中，原版两次均值 38.861 秒，优化版均值 27.670 秒，观测到约 40.45% 吞吐提升。但单次波动较大；对外优先采用更稳定的 12×4、约 21.1% 结果。

验证包括：

- 1,800 次历史查询逐张量精确相同，覆盖长度 1/4/16、同 tick、未知事件和 reset。
- 8 项负向保护测试，优化前后权重张量不变。
- 独立参考模型 2,125 次前向对照，该组数据的输出与 hidden 最大误差均为零。
- 1,000 次 scalar/batched 动作相同，浮点差异沿用既定 `atol=1e-4, rtol=2e-4` 容差；不要混称全部浮点都逐位相同。
- 新宿主与黄金轨迹 6,152 次观测对照，604 次已接受动作，30 次活跃槽位重置，其他槽位不受影响。
- 单进程各版本与高并发 A/B/B/A 全部通过动作摘要及终局一致性检查。

尚未证明：所有卡组/模式/新版本内核、GPU 故障恢复、学习器并发、24 小时无人值守，以及模型强度提升。

## 6. 启动故障与处理

首次并发启动在原版 worker 1 报 `java.net.BindException: EADDRINUSE`，发生在策略加载前，退出码 3，OOM 为零。失败记录保留，没有计入吞吐样本。

旧端口 41431/42431 位于机器临时端口范围 32768–60999 内。没有确定当时具体占有者，所以不把“必定由临时端口造成”当作已证实结论。

后续新旧对照统一改到 24431/25431 起，原样运行成功。没有修改系统网络参数，没有终止不属于测试的程序。
