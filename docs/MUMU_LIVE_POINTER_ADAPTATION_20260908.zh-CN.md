## 已实测指针链

每次重新读取进程的 libg 映射基址，不能持久化上一次 ASLR 地址。

```text
libg_base + 0x1A569A8 → manager
manager + 0x28       → context
context + 0x90       → battle
  ├─ +0x60           → native tick (int32)
  ├─ +0x1BC          → applied replay tick (int32)
  └─ +0xA8           → player/scene state
       ├─ +0xE0      → side 0 player (King entity)
       ├─ +0xE8      → side 1 player (King entity)
       └─ +0x08      → registry
            └─ +0x40 → collection
                 ├─ +0x08 → entity pointer array
                 └─ +0x14 → entity count (int32)
```

玩家字段：

| 字段 | 偏移/表示 |
| --- | --- |
| 手牌索引数组 | `+0x210` 指针，`+0x218` 容量，`+0x21C` 长度 |
| 循环队列 | `+0x220` 指针，`+0x228` 容量，`+0x22C` 长度 |
| 下一张 | 循环队列第一个索引 |
| 圣水 | `+0x2F8` int32；10000 表示一费 |

自身完整八卡及形态继续通过 `read_visible_deck` 的 avatar/owner/deck entries 链读取，而非配置里固定另一套卡组。对手手牌隐藏时不尝试恢复其真实手牌。回放/结算画面可能显示双方手牌，不代表有两个可控制的己方。

单位/塔的坐标、类别、卡牌ID、等级、HP 及行为状态偏移见 `bindings/mumu-live-160402002-arm64.json`。保留形态 ID，例如实测的 `203000076`，不因超出 25xx/29xx 常规卡号范围而静默丢掉。

## 工程修改

1. 合并实体与玩家为一个 `mumu_live_frame`，同一轮采样读 Tick 前后并检查 manager/context/battle 身份未改变。控制器不再拼接相差两个 Tick 的两个独立流。
2. 固定 `battle + 0xA8` 玩家入口。最终统一读取模式不做堆/BFS 搜索；加载时字段尚未初始化就返回 unresolved。
3. 单个常驻 ADB 采样进程，不在热路径不断调用 `mumu-cli sh` 创建 NemuShell。主控制器不再默认启动/切换安卓实例。
4. 启动前检查 versionCode、ABI 和 **libg 文件 SHA256**；仅核对版本号是不够的。
5. `BattleClockGuard` 区分对象可读与时钟推进。暂停/停滞、双方手牌可见、无法确定己方、无有效场景、已毁国王塔等情况不允许模型控制。
6. 对局地址或 Tick 回退会改变 epoch，控制器释放旧隐藏状态、待确认动作并重新绑定。
7. 同一局结束后旧对象依然可能存在，不能用非空指针作为“正在对局”的唯一条件。

`coherent=true` 是 Tick/指针括号检查通过，不等于暂停了引擎线程或取得绝对原子快照。
