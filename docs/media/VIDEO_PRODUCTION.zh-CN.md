# 视频拍摄、画面与事实核验清单

配套 [完整口播稿](VIDEO_SCRIPT.zh-CN.md)。技术截点 2026-09-12；本文件整理素材与事实，不启动云测试、不自动操作游戏、不生成虚构实拍。

## 一、项目地图：哪些东西属于哪条路线

| 层 | 职责 | 当前边界 |
|---|---|---|
| 数据来源与资格检查 | 保存来源、版本、去重、动作可信度 | 历史统计不等于当前全量规模；缺锚点复演不是原比赛精确恢复 |
| `expert_v1/` | 原生动作复演、Tick 存储、专家训练 | 多版本历史链路，不能与最新发布模型混为一个训练结果 |
| `native_core/` | Python 客户端、环境、卡牌/动作路由、可视化 | 本身不演算伤害和移动 |
| `android_probe/` | Java 宿主、JNI 桥、版本绑定、原生对局 | 默认宿主与多局实验快照分开 |
| Linux Bionic 独立仓库 | 匹配的 Android 用户态、无 AVD 启动 | 已验收的是冻结旧版 x86_64；新版 ARM64 不套用这些结果 |
| MuMu 实时工具 | 当前客户端只读观察、普通触摸与回执 | 与 Linux 无头沙盒分开；不把本地原生命令调用讲成在线动作方式 |
| 旧 `expert_selfplay_v1/` | 177M 路线的实际 Critic/PPO | 历史阶段对手固定 BASE，联赛未接主循环 |
| `training_r0/` | 独立的新架构设计与离线内核 | 不是本轮 4.804M Graph/学习小闭环使用的网络 |
| `experiments/resident_linux_20260912/` | 四局驻留及后续优化、真实学习小测试 | 独立实验，不自动替换默认宿主或正式模型 |

## 二、建议剪辑结构

以下时长可按实际口播缩放，主稿正文约四千汉字，加演示停顿可按约 15～18 分钟安排。

| 段落 | 建议时长 | 画面重点 | 屏幕上只保留的关键词 |
|---|---:|---|---|
| 开场 | 30～40 s | 对局盒子短片＋Linux 进度 | 观察／行动／推进／学习 |
| libg.so 定义 | 60～90 s | 库、宿主、资源三者关系 | 原生战斗逻辑；版本锁定 |
| 指针链原理 | 100～140 s | 一层层读取指针；暂停/播放/换局对比 | 相对地址；解引用；跨局重绑定 |
| 两条接口路线 | 90～120 s | MuMu 与沙盒左右分屏；API 表 | 实时读取＋触摸／本地原生命令 |
| Linux 部署 | 60～90 s | 用户态依赖链；无 AVD | Bionic／ART／JNI／libg |
| 四局驻留 | 70～100 s | 一个执行标记轮流访问 A/B/C/D | 驻留≠同进程多线程重入 |
| 模型输入与时机 | 60～90 s | 实体、网格、历史；WAIT/PLAY | 20Hz 原生 Tick；每4Tick决策 |
| 数据与学习闭环 | 100～140 s | 数据来源标签、双进程队列、8次更新 | 样本版本；h0；bootstrap；非空动态场景 |
| 性能与失败实验 | 100～140 s | 同硬件表格；一成功、一失败案例 | 聚合采集速度；同轨迹；显存代价 |
| 现状与下一步 | 45～70 s | 已验证与待完成分别列出 | 动态对手；独立评估；完整训练 |

不要把全部控制台日志一次铺满画面。口播讲一件事时，画面只高亮相应字段。

## 三、四张核心技术示意图的内容

### 图 A：两个运行路径

```text
实时验证：MuMu 中的客户端 → 只读采样 → 公共视角编码 → 模型 → 普通触摸 → 回执

本地训练：采集器 ↔ Java/JNI 宿主 ↔ 原版 libg 的战斗对象
             ↓
        真实观察与动作记录 → 学习器 → 经过验证的策略快照
```

标注“示意图”。不能把“普通触摸”画到 Linux 无头推进链，也不能把沙盒原生命令画成在线客户端操作方式。

### 图 B：指针链与相对地址

```text
模块映射基址
    + 全局槽位 RVA
    ↓ 读取这个位置保存的指针
管理对象
    + 对象字段偏移
    ↓ 再次读取指针
战斗状态 / 战斗对象
    ├─ Tick
    ├─ 玩家
    └─ 实体集合 → 实体数组 → 单位的坐标、血量等字段
```

函数地址用 `module_base + function_RVA` 表示；对象链则是多次“加偏移后解引用”。不要把整条链画成一次连续加法。

可选加长技术段（不必全部塞进口播）：

- **静态定位**：从可识别的 JNI 入口、调用关系或稳定引用寻找候选；反汇编中的工程命名不一定是原厂符号。
- **对象布局**：构造、更新和释放函数如何读写同一片字段，能帮助判断对象职责；不能只凭一次内存扫描给字段命名。
- **类型与单位**：指针、int32、float 和定点数要分开解释。MuMu 已验证记录中，圣水原始值 10000 表示一费，而不是直接按 float 读取。
- **地址生命周期**：模块映射受 ASLR 影响；战斗对象也会随换局重建。动作路由应使用本局稳定实体身份，不将进程地址作为永久 ID。
- **动态验证**：暂停、播放、手动下牌、结算、新局分别改变什么字段；需要多场景交叉验证，不能只检验一个“像 Tick”的数值。
- **同帧检查**：读 Tick/对象身份前后是否一致；这只是检测混帧风险，不等于持有引擎锁。

如果需要展示真实地址，只截取对应版本文档的一小段，并同时显示版本/ABI；具体地址不是旁白重点。

### 图 C：单进程四局

```text
一组采集 worker
├─ 原生进程：一个执行通道，A → B → C → D 交错推进
├─ A/B/C/D：独立战斗状态与各自的结束/重置
└─ 策略进程：独立的玩家记忆 → 合批推理 → 把动作分发回正确对局

多组 worker 再由外层并行运行
```

外层标“12组 / 48局驻留”；不要写“整台仅12进程”“一个线程真正同时算4局”。

### 图 D：已验收的异步小闭环

```text
采集进程：行为策略 v → 原生对局 → 32步×4学习方的数据段
                                  ↓
                         容量2的队列 / 版本准入
                                  ↓
学习进程：联合概率重算 → PPO与价值头更新 → 校验 → 发布新头部快照
                                  ↓
                     在采集段边界应用；主干/LSTM冻结
```

标注“输出头微调小测试，不是全网络联赛”。不把队列画成无限堆积，不把异步画成完全没有策略版本限制。

## 四、libg 接口可上屏的最小表格

| 接口 | 给观众的解释 |
|---|---|
| `reset` | 建立新对局或重置已有运行槽 |
| `observe` | 读取完整诊断观察 |
| `observe_train_v1` / `train-v1` | 按明确训练合同读取紧凑观察 |
| `step(N)` | 推进 N 次原生更新；结算时看实际完成值 |
| `probe_grid` | 询问当前卡牌的合法部署区域 |
| `act` / `ability` | 普通下牌／主动技能 |
| `joint_transition` | 双方动作、推进、下一状态合并 |
| `resident_batch` | 多驻留槽位的批量动作和推进 |

这些是项目包装的接口，不应说成官方提供的公开训练 SDK。完整接口见 [沙盒技术文档](../SANDBOX_RUNTIME_TECHNICAL.zh-CN.md)。

## 六、视频数字口径卡

| 数字 | 可以说什么 | 不能说什么 |
|---|---|---|
| 20Hz | 绑定版本每次原生核心更新的游戏时间步长为0.05秒 | 游戏画面必然只有20FPS |
| 4 Tick | 当前4.804M路径每200ms游戏时间做一次决策 | 每200ms一定下牌；所有历史模型都用4Tick |
| 4,804,205参数 | 本轮接入模型的可训练参数数目 | 把旧177M直接压缩成了这个模型 |
| 12×4 | 12组采集worker、48局驻留 | 单进程4线程安全重入；整机只有12进程 |
| 6,227.8→7,028.7 tick/s | 第三轮同硬件、同模型、同种子的多局聚合采集对照 | 单局7,000FPS；完整学习吞吐；数学证明全部逻辑相等 |
| +12.86% | 本轮Graph组合相对本轮对照的吞吐提升 | 与前轮百分比直接相乘作为严格总收益 |
| 8,446→11,020MiB | 本轮12组策略进程的实测显存峰值 | 单个小模型权重就有11GB |
| -57.92% | 紧凑观察验证样本的JSON序列化字节减少 | 训练快58%；所有数据集体积少58% |
| 1,024样本／8次更新 | 新模型输出头异步学习短测 | 1,024场比赛；8轮完整全网络训练 |
| 697移动帧／607网格状态 | 短测确实观察到动态场景和不同模型输入 | 所有帧都有新单位；模型必然作出合理防守 |
| 历史policy19→20→21 | 旧177M路线有真实PPO更新记录 | 当前4.804M已经跑完同样的正式联赛 |

## 七、录制前核对

- 账号密码、SSH 命令旁的密码、Token、邮箱、账户余额、聊天内容和无关桌面窗口不要入镜。
- 日志回放要标注记录日期；预录/加速播放要说明，不能表现成实时帧率。
- 选择本地沙盒或已授权的测试场景演示，不自动启动线上比赛。
- 两种 ABI、两种客户端路线、三条模型/训练历史必须分清。
- 所展示的模型来源、协作者贡献和参考项目按已核实信息署名；不要把接入权重写成独立原创训练成果。
- 不展示或重新打包私有数据集、游戏资源、权重或凭据来充当视频附件。
- “原生战斗计算”不等于整个客户端零适配；“同字段/动作一致”不等于所有内存状态完全一样。
- 不以单局赢人、低 loss 或对固定对手的训练胜率，宣传已经超过人类或达到某个段位。
- 正式训练、动态对手池和长期故障恢复仍待验收，片尾保留这条边界。
