# 落点分支稳定性试验（2026-08-30）

## 结论与当前状态

本轮试验已完成。推荐进一步验证的候选是：**落点打分用FP32计算，并使用中心化softcap，阈值20**。

在本次GPU压力对照中，只降低落点分支学习率、或仅改FP32，都没有消除极端Loss/梯度；FP32+softcap20显著减轻了这类异常。正常存档的小样本确认未见大幅退化，但不足以证明长期稳定或实战胜率提高。

**正式训练没有自动切换方案，现已安全暂停。** 可恢复的最新正式存档是123,740步；停机前最后进度记录为123,837步，二者不可混淆。GPU试验均已结束，云实例未关机。

## 对照设计

- 同一数据版本、同一起点、同一批次顺序；不重跑libg、不改原训练集、标签、Loss公式或各项权重。
- 模型177,092,661参数，Batch 32，目标序列128、burn-in 32，主干BF16，梯度裁剪1.0。
- 系统可见128逻辑核，但cgroup CPU时间配额为16核；CPU筛选使用2进程×6线程，样本准备使用4进程。
- CPU：4份存档×17批次=68次主干前向，复用编码完成408组落点评分对照。仅重算具有落点监督的行。
- CPU候选：原BF16、落点FP32、中心化softcap10/20、QK向量归一化scale16/32。
- GPU压力对照：4组，每组150次优化器更新，共同起点为上一低学习率实验的139,207步失稳存档。
- GPU正常确认：2组，每组300次更新，共同起点为当前108,272回退实验保存的123,740步模型。
- 所有GPU试验合计1,200次更新。压力组验证为256个序列；正常确认扩大到1,024个序列、759个有效下牌/落点标签。
- 保留原有split命名：训练用`validation`，验证用`train`；没有重新划分数据，未使用`test`分区作调参依据。

## 候选打分方式

设原落点分数为`score = query · cell / sqrt(embedding_dim)`。候选将落点查询、格子投影及点积放在FP32中计算，再对每行所有格子分数使用：

`score_new = 20 * tanh((score - mean(score)) / 20)`

随后仍按原规则施加合法位置mask及交叉熵。**不是截断Loss，也没有调小位置Loss权重。** 改变的是概率分布的打分函数及相应梯度。

试验只替换普通下牌的落点计算；其他输出头保留原路径。为控制显存，训练时只重算实际有监督的手牌/时间行；单元测试核对了该稀疏实现与密集FP32实现的Loss和参数梯度一致，并覆盖无落点标签时的零梯度行为。

## 正常存档确认：同一123,740步起点，各300步

以下验证使用完全相同的1,024个序列，并按正式`MetricAccumulator`规则汇总。

|---|---:|---:|

两组均无NaN/Inf/OOM或Loss>10。速度差异很小，不能据此承诺固定百分比加速；本实现未显示明显吞吐损失。显存数字为PyTorch峰值已分配量，不等同于驱动显示的全部保留显存。

选牌Top-1下降约0.26个百分点（759个标签中约2个），并非所有指标均改善。

## 不确定性与验收边界

对正常确认的32个验证批次作10,000次成对bootstrap，候选减基线：

- 验证Loss差：-0.0190，近似95%区间[-0.0499, +0.0041]，仍跨0，不能称为显著验证Loss提升。
- 平均落点误差差：-0.1436格，区间[-0.2373, -0.0453]。
- 选牌准确率差：-0.2635个百分点，区间约[-1.1423, +0.6667]个百分点。

这些只是固定小样本、单训练seed下的批次重采样区间；不覆盖训练随机性、候选筛选偏差或实战变化。没有完成整轮验证、长程稳定性测试或对战胜率验收。

CPU筛选的梯度只涉及落点头，不能与上述GPU全网络梯度混用。CPU表的Loss为批次算术均值；GPU验证保留正式汇总的权重规则，不能跨阶段直接比较绝对值。未测量的CPU梯度在合并报告中为null，不表示梯度为零。
